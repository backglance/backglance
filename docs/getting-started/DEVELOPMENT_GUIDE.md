# Development Guide

Last Updated: 2026-08-18

This guide is for anyone changing Backglance's code. It explains how the repository is laid out and why, what each Swift package owns, the naming and style conventions the linters enforce, how we use git, how to work on the capture layer without ever putting real notification data at risk, how tests are organised, what a reviewer looks for, and the handful of commands you will use every day. It assumes you have a working build; if not, start with [SETUP_GUIDE.md](./SETUP_GUIDE.md).

Why it is split this way:

- **The app target is a thin shell.** Everything under `Backglance/App/` is AppKit plumbing that cannot live in a package without dragging `NSApplication` into tests: the status item, the popover, the Carbon hotkey, launch-at-login, the URL scheme handler, and the Sparkle controller. `Scenes/` holds the SwiftUI screens that compose views from `BackglanceUI` with app-level state.
- **Packages are the unit of testing.** Each package has its own test bundle and can be built and tested with `swift build` / `swift test` from its directory, without Xcode, which is what CI does for the fast path.
- **`Tests/Fixtures/` is data, not code.** It is checked in, versioned, and regenerated by script. Nothing in it is real. See [Debugging the capture layer safely](#debugging-the-capture-layer-safely).
- **`Scripts/` is bash, not Swift.** They are meant to be readable in a code review and to run on a bare CI runner. The one exception is `make_fixture.sh`, which shells out to a Swift executable target because generating a bplist by hand in bash is not something anyone should maintain.

## Code organisation per package

### BackglanceCore

Owns the **archive** (Backglance's own SQLite database), every model that is persisted in it, and every piece of pure logic that runs on archived notifications.

```
Packages/BackglanceCore/Sources/BackglanceCore/
├── Archive/
│   ├── Archive.swift              # final class Archive: wraps DatabasePool; .shared; init(inMemory:)
│   ├── ArchiveMigrations.swift    # DatabaseMigrator: v1_initial, v1_fts, v2_saved_searches, …
│   ├── ArchivePaths.swift         # default path, BACKGLANCE_ARCHIVE_PATH override, 0600/0700
│   └── UnixDate.swift             # DatabaseValueConvertible wrapper: Date <-> REAL Unix seconds
├── Models/
│   ├── ArchivedNotification.swift, AppRecord.swift, Rule.swift, Digest.swift, DigestItem.swift,
│   ├── RedactionEvent.swift, AwaySession.swift, CaptureState.swift,
│   └── SavedSearch.swift, Snooze.swift, Embedding.swift        # v1.x
├── Retention/     RetentionPolicy.swift, RetentionJob.swift
├── Redaction/     OTPRedactor.swift, OTPPatterns.swift
├── Rules/         RulesEngine.swift, Triage.swift
├── Digest/        DigestEngine.swift, AwaySessionTracker.swift, AwayReason.swift
├── Export/        ExportService.swift, CSVWriter.swift
├── Privacy/       PanicWipe.swift, ExclusionList.swift
└── Reminders/     SnoozeScheduler.swift                        # v1.x
```

Rules of thumb: no `import AppKit`, no `import SwiftUI`. `Foundation`, `GRDB`, `os`, and (for `SnoozeScheduler`) `UserNotifications`/`EventKit` are the only imports. If a type needs to know about the screen, it does not belong here.

### BackglanceCapture

Owns everything that touches the **system store**: locating it, watching it, fingerprinting it, choosing an adapter, reading records, and turning them into `ParsedNotification` values. This is the fragile package; the ⚠️ markers in the docs all point here.

```
Packages/BackglanceCapture/Sources/BackglanceCapture/
├── CaptureEngine.swift            # actor; start/pause/resume/importExisting; publishes CaptureStatus
├── CaptureStatus.swift            # .running / .paused(until:) / .degraded(DegradedReason) / .stopped
├── Store/
│   ├── StoreLocation.swift        # static func current() throws -> URL (+ BACKGLANCE_STORE_PATH in DEBUG)
│   ├── StoreWatcher.swift         # DispatchSource on db/-wal + poll fallback + wake/unlock triggers
│   ├── StoreSnapshot.swift        # copy db+wal to tmp/, open read-only with ?immutable=1
│   ├── StoreFingerprint.swift     # SHA-256 of sqlite_master SQL + dbinfo version + OS version
│   └── StoreCursor.swift          # lastRecID + lastDeliveredDate, persisted in capture_state
├── Adapters/
│   ├── StoreAdapter.swift         # protocol StoreAdapter: Sendable
│   ├── StoreAdapterRegistry.swift # resolve(fingerprint:) -> (any StoreAdapter)?
│   ├── StoreAdapterV14.swift, StoreAdapterV15.swift, StoreAdapterV26.swift
│   └── ProbeResult.swift
├── Parsing/
│   ├── RawStoreRecord.swift
│   ├── RecordParser.swift         # bplist -> ParsedNotification (keys: app, date, req.titl/subt/body/…)
│   └── ParsedNotification.swift
└── Enrichment/
    ├── EnrichmentService.swift    # icons via NSWorkspace, icon cache, deep-link resolution
    └── DeepLinkResolvers/         # Messages, Mail, Slack, Discord, Generic
Packages/BackglanceCapture/Sources/FixtureGenerator/            # executable target used by make_fixture.sh
```

`EnrichmentService` is the one place in this package that imports `AppKit` (for `NSWorkspace`); it is isolated so the rest of the package stays testable on the command line.

### BackglanceSearch

Owns the FTS5 index over the archive, the query language, fuzzy matching, the optional semantic index, and the hybrid ranker.

```
Packages/BackglanceSearch/Sources/BackglanceSearch/
├── FTSIndex.swift          # notifications_fts external-content table + triggers, MATCH queries
├── QueryParser.swift       # "from:slack before:2026-08-01 invoice" -> SearchQuery
├── SearchQuery.swift, SearchHit.swift
├── FuzzyMatcher.swift      # Levenshtein, threshold 0.6 (ported from PasteShelf)
├── Semantic/
│   ├── SemanticIndex.swift        # NLEmbedding.sentenceEmbedding(for: .english), batches of 50
│   ├── VectorSimilarity.swift     # cosine similarity, brute-force top-K
│   └── EmbeddingStore.swift       # embeddings table (BLOB of 512 Float32)
└── HybridSearch.swift      # weights FTS 0.4 / semantic 0.5 / fuzzy 0.3
```

The semantic engine (`SemanticIndex`, `VectorSimilarity`, `HybridSearch`, `FuzzyMatcher`) is a port of PasteShelf's `EmbeddingManager` / `SemanticSearchEngine` / `VectorSimilarityCalculator` / `HybridSearchEngine` / `FuzzyMatcher`. The storage differs — PasteShelf uses Core Data, Backglance uses GRDB — so the port is the algorithm, not the persistence. When touching these files, keep the algorithm diffable against the PasteShelf originals; do not "improve" the scoring without a benchmark.

### BackglanceUI

SwiftUI views shared by the popover, the timeline window, and (v1.x) the widgets. No business logic and no direct database access: views take models and closures.

```
Packages/BackglanceUI/Sources/BackglanceUI/
├── Timeline/    TimelineView.swift, NotificationRow.swift, DayHeader.swift, EmptyState.swift
├── Digest/      DigestView.swift, DigestSection.swift
├── Search/      SearchBar.swift, SearchScopePicker.swift
├── Settings/    GeneralSettingsView.swift, AppsSettingsView.swift, RulesSettingsView.swift,
│                PrivacySettingsView.swift, RetentionPicker.swift
├── Components/  AppIconView.swift, HighlightBadge.swift, CaptureStatusBanner.swift
└── Preview/     PreviewData.swift          # synthetic sample data for #Preview only
```

Every view has a `#Preview` using `PreviewData`, and every interactive element has an accessibility label. Strings go through the String Catalog (`Localizable.xcstrings` in the app target; the package uses `Bundle.module` for its own catalog).

### App target

`Backglance/App/` wires the packages together. `AppDelegate` creates `Archive.shared`, starts `CaptureEngine`, and hands both to `StatusItemController`, which owns the `NSStatusItem` and the `NSPopover` hosting an `NSHostingController` from `BackglanceUI`. `HotKeyCenter` wraps Carbon `RegisterEventHotKey` for ⌃⌥N. `URLSchemeHandler` maps `backglance://` URLs to actions. `SparkleUpdaterController` is created only if `SUPublicEDKey` is present in `Info.plist` and `BACKGLANCE_DISABLE_UPDATER` is unset.

### Dependency direction

```
        ┌──────────────────────────────┐
        │        Backglance (app)      │
        └──┬──────────┬──────────┬─────┘
           │          │          │
           ▼          ▼          ▼
   BackglanceUI  BackglanceSearch  BackglanceCapture
           │          │          │
           └──────────┴──────────┘
                      ▼
               BackglanceCore
                      ▼
                  GRDB.swift
```

`BackglanceCore` depends on nothing of ours. `BackglanceCapture`, `BackglanceSearch`, and `BackglanceUI` depend on `BackglanceCore` and never on each other. The app depends on all four. A change that needs `BackglanceUI` to import `BackglanceCapture` is a design smell; pass a `CaptureStatus` value down instead.

## Naming conventions

| Thing | Convention | Examples |
|---|---|---|
| Types | `UpperCamelCase`, nouns; protocols are nouns or `-able`/`-ing` | `StoreAdapter`, `RecordParser`, `ArchivedNotification`, `Sendable` |
| Adapters | `StoreAdapterV<major>` — the macOS major version the schema first appeared in | `StoreAdapterV14`, `StoreAdapterV26` |
| Enums with raw values | lowerCamelCase cases, explicit `String` raw values matching the archive column vocabulary | `RetentionPolicy.days30 = "30d"`, `AwayReason.presenting` |
| Files | one primary type per file, file named after it; extensions in `Type+Feature.swift` | `StoreWatcher.swift`, `Archive+Retention.swift` |
| Test files | `<Type>Tests.swift` for unit tests, `<Feature>IntegrationTests.swift` for cross-type tests, `Fixture<OS>Tests.swift` for fixture runs | `OTPRedactorTests.swift`, `CaptureIntegrationTests.swift`, `FixtureMacOS26Tests.swift` |
| XCTest methods | `test_when<Condition>_then<Outcome>` | `test_whenBodyIsOnlyDigits_thenRedactsWholeBody` |
| Swift Testing | `@Test("plain sentence describing the behaviour")` | `@Test("degraded when fingerprint matches no adapter")` |
| Log categories | lower-case, one word, matching the package or subsystem | `capture`, `archive`, `search`, `digest`, `ui`, `updater` |
| Archive columns | `snake_case`, times end in `_at`, booleans start with `is_` | `delivered_at`, `is_pinned` |
| Migrations | `v<archive_version>_<what>` | `v1_initial`, `v2_saved_searches` |
| Env vars | `BACKGLANCE_` prefix, `UPPER_SNAKE` | `BACKGLANCE_STORE_PATH` |
| Scripts | `snake_case.sh`, verb first | `make_fixture.sh`, `grant_fda_hint.sh` |
| Feature branches | `feat/`, `fix/`, `docs/`, `chore/` + short kebab-case | `feat/capture-v27-adapter` |

Terminology in identifiers follows the docs: it is a *notification* (never an alert), the *archive* is ours, the *store* is Apple's, an *adapter* reads one store schema, a *fixture* is a synthetic store, and an *away session* is what the digest summarises. `Store*` types live in `BackglanceCapture`; `Archive*` types live in `BackglanceCore`. If you find yourself writing `SystemDB` or `HistoryStore`, rename it.

## Swift style guide

Language mode is Swift 5 (Swift 5.10+), building under the Swift 6 toolchain with `SWIFT_STRICT_CONCURRENCY = complete` as the goal. Formatting is enforced by SwiftFormat and SwiftLint; both run in the pre-commit hook when installed and in CI always. Match the existing code and let the tools argue about spaces.

### Concurrency: actors, MainActor, Sendable

- **`CaptureEngine` is an `actor`.** All mutation of capture state goes through it. It exposes `AsyncStream<CaptureStatus>` for observers; it never calls into UI.
- **UI-facing state is `@MainActor`.** View models in `Backglance/Scenes/` are `@MainActor final class … : ObservableObject` (or `@Observable` where the deployment target allows; both are fine on macOS 14). Nothing that touches AppKit runs off the main actor.
- **`Archive` is thread-safe by construction** through GRDB's `DatabasePool`; it is `Sendable` and can be handed to any actor. Reads use `archive.read { db in … }`, writes use `archive.write { db in … }`; long imports use `archive.writeInTransaction`.
- **`StoreAdapter` conformances are `Sendable` structs** with no stored mutable state. If an adapter needs a cache, put it in the engine.
- **Models are `Sendable` value types.** `ArchivedNotification`, `ParsedNotification`, `RawStoreRecord`, `StoreFingerprint`, and friends are structs of `Sendable` fields. `Data`, `Date`, `UUID`, `URL` are all fine.
- **`@unchecked Sendable` requires a comment** explaining what invariant makes it safe. There are two in the codebase (`HotKeyCenter` wrapping a Carbon handle and `IconCache` guarding an `NSCache`), and reviewers will push back on a third.
- **No `DispatchQueue.main.async` in new code.** Use `await MainActor.run { }` or mark the function `@MainActor`. `DispatchSource` is used in `StoreWatcher` because that is what the file-system API gives us; its events are forwarded into the actor with `Task { await engine.storeDidChange() }`.
- **Warnings are errors for concurrency diagnostics in files you touch.** Pre-existing warnings on `main` are tracked in issues labelled `concurrency`; do not fix unrelated ones in a feature PR.

```swift
// A typical safe pattern: a DispatchSource callback hopping into the actor.
final class StoreWatcher {
    private let source: DispatchSourceFileSystemObject
    private let onChange: @Sendable () async -> Void

    init(fileDescriptor: Int32, queue: DispatchQueue, onChange: @escaping @Sendable () async -> Void) {
        self.onChange = onChange
        source = DispatchSource.makeFileSystemObjectSource(
            fileDescriptor: fileDescriptor,
            eventMask: [.write, .extend, .rename, .delete],
            queue: queue
        )
        source.setEventHandler { [onChange] in
            Task { await onChange() }
        }
        source.setCancelHandler { close(fileDescriptor) }
        source.resume()
    }

    deinit { source.cancel() }
}
```

### Errors

- Each package has one public error enum: `ArchiveError`, `CaptureError`, `SearchError`. Cases carry context, not strings: `case migrationFailed(name: String, underlying: Error)`, not `case failed(String)`.
- Errors conform to `LocalizedError` only when they are shown to the user; internal ones do not.
- `DegradedReason` is not an error. It is a state. Do not `throw` a degraded condition from `CaptureEngine`; set the status and return.
- Do not swallow errors with `try?` unless the comment above says why the failure is acceptable.

```swift
public enum CaptureError: Error, Sendable {
    case storeNotFound(searched: URL)
    case snapshotFailed(underlying: Error)
    case unknownSchema(StoreFingerprint)
    case parse(recID: Int64, underlying: Error)   // never includes record contents
}
```

### Optionals and force unwraps

No `!`, `try!`, or `as!` outside `Tests/`. Use `guard let`, `XCTUnwrap`, or a thrown error. `IBOutlet`s do not exist in this project, so the implicitly-unwrapped exemption never applies.

```swift
// ✅
guard let url = Bundle.main.url(forResource: "default_exclusions", withExtension: "json") else {
    throw ArchiveError.missingResource("default_exclusions.json")
}

// ❌
let url = Bundle.main.url(forResource: "default_exclusions", withExtension: "json")!
```

### Logging and privacy

Every log line goes through `os.Logger(subsystem: "app.backglance.Backglance", category: …)`. The file log at `~/Library/Logs/Backglance/backglance.log` mirrors the same messages (rotating, max 5 × 2 MB), so anything you log is on disk in plain text.

- **Never log notification content.** Not title, subtitle, body, sender, thread ID, `userInfo`, `plistData`, or attachment names. Log bundle IDs, record IDs, UUIDs, counts, durations, and status enums.
- **Use `privacy: .public` deliberately.** By default `os.Logger` redacts interpolated non-literal values as `<private>` in unified logging. Mark identifiers and counts `.public` so debugging is possible; leave anything that could be user-derived text at the default. This is a second line of defence, not a substitute for the first rule.
- **Never log the archive path or store path at `.info` or above** with `.public`; they contain the user's home directory. `debug` is fine.

```swift
import os

let logger = Logger(subsystem: "app.backglance.Backglance", category: "capture")

// ✅ identifiers, counts, status
logger.info("adapter resolved: \(StoreAdapterV26.id, privacy: .public) records=\(batch.count, privacy: .public)")
logger.debug("cursor advanced to recID=\(cursor.lastRecID, privacy: .public)")
logger.error("snapshot failed: \(error.localizedDescription, privacy: .public)")

// ❌ content — the SwiftLint rule `no_content_in_logs` fails the build on these
// logger.debug("parsed \(parsed.title ?? "") from \(parsed.sender ?? "")")
```

## Git workflow

- **`main` is always releasable.** CI must be green; direct pushes are blocked.
- **Short-lived feature branches** off `main`: `feat/…`, `fix/…`, `docs/…`, `chore/…`. Rebase on `main` rather than merging `main` in. Aim for branches that live days, not weeks.
- **Conventional Commits.** `type(scope): imperative summary`, where type ∈ `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `chore`, `ci`, `build` and scope is a package or area: `capture`, `core`, `search`, `ui`, `app`, `digest`, `rules`, `fixtures`, `scripts`, `docs`. Breaking changes (rare; there is no public API yet) get a `!` and a `BREAKING CHANGE:` footer.

  ```
  feat(capture): add StoreAdapterV27 with fingerprint from 27.0 beta 3
  fix(digest): do not create a digest for away sessions shorter than 5 min
  test(fixtures): regenerate macOS26 fixture after presented-flag change
  docs(setup): explain per-path FDA grants
  ```

- **Pull requests are squash-merged.** The PR title becomes the commit subject, so write it as a conventional commit. The squash body should keep the meaningful bullets from the PR description; drop "address review comments".
- **Tags are `v<semver>`** on `main`, created by the release workflow: `v1.0.0`, `v1.0.1`, `v1.1.0-beta.1`. Tags are what CI builds, signs, notarizes, and publishes; see [DEPLOYMENT_GUIDE.md](../deployment/DEPLOYMENT_GUIDE.md).
- **No release branches.** With a single developer and a squash-merged `main`, a release is a tag. Hotfixes go to `main` and get a new patch tag. If a `1.0.x` line ever needs to diverge from `main`, that is the moment to introduce a `release/1.0` branch, not before.
- **CHANGELOG.md is updated in the PR** that makes the change, under `[Unreleased]`, in Keep-a-Changelog categories. The release workflow moves it under the version heading.
- **Signed commits are encouraged, not required.** Contributors are asked to certify DCO-style with `Signed-off-by:` (`git commit -s`); see [CONTRIBUTING.md](../contributing/CONTRIBUTING.md).

Pre-commit hook (`Scripts/hooks/pre-commit`, installed by `bootstrap.sh`):

```bash
#!/usr/bin/env bash
# Scripts/hooks/pre-commit — format + lint staged Swift files; refuse to commit a store copy.
set -euo pipefail

STAGED_SWIFT="$(git diff --cached --name-only --diff-filter=ACM | grep -E '\.swift$' || true)"

if [[ -n "$STAGED_SWIFT" ]]; then
  if command -v swiftformat >/dev/null 2>&1; then
    # shellcheck disable=SC2086
    swiftformat --lint $STAGED_SWIFT || { echo "run: swiftformat ." >&2; exit 1; }
  fi
  if command -v swiftlint >/dev/null 2>&1; then
    # shellcheck disable=SC2086
    swiftlint lint --strict --quiet $STAGED_SWIFT
  fi
fi

# Guard against accidentally staging a real system store or a private archive.
if git diff --cached --name-only | grep -Eq '(^|/)(db|db-wal|db-shm|archive\.sqlite(-wal|-shm)?)$'; then
  echo "error: refusing to commit what looks like a system store or archive file." >&2
  echo "       Fixtures are generated by Scripts/make_fixture.sh and named store.db." >&2
  exit 1
fi
```

## Debugging the capture layer safely

The system store contains every notification the user has received recently: messages, mail subjects, one-time codes, calendar invitations. Treat a copy of it as you would treat a copy of someone's inbox.

> ❌ **Don't:** commit a copy of a real system store, attach one to an issue, paste rows from one into a chat, or "temporarily" put one under `Tests/Fixtures/`. There is no legitimate reason for real store contents to leave your machine.

> ✅ **Do:** work against fixtures, and when you must look at your own live store, inspect **schema only** from a copied snapshot opened read-only.

**`.gitignore` entries that back this up** (already in the repository):

```
# Local overrides and scratch
Config/Local.xcconfig
.local/

# Never commit a real system store or a private archive
db
db-wal
db-shm
*.usernoted*
archive.sqlite
archive.sqlite-wal
archive.sqlite-shm
Tests/Fixtures/**/*.real.*
Tests/Fixtures/**/scratch/
```

**Use a fixture first.** For almost every capture bug you can reproduce the failing shape in a fixture: `Scripts/make_fixture.sh --os 26 --records 5`, then edit `manifest.json`'s generator parameters, or add rows with `sqlite3` to a copy under `.local/`. Run the app with `BACKGLANCE_STORE_PATH` pointing at it (see [SETUP_GUIDE.md](./SETUP_GUIDE.md#running-against-a-fixture)).

**When you genuinely need your own store** — typically when a new macOS changed the layout — copy it and read the schema, nothing more:

```bash
# 1. Snapshot into a scratch dir outside the repo. Copy db + wal + shm together
#    so the copy is consistent; the WAL may hold recent rows.
SNAP="$(mktemp -d "${TMPDIR:-/tmp}/bg-store-XXXXXX")"
cp ~/Library/Group\ Containers/group.com.apple.usernoted/db2/db{,-wal,-shm} "$SNAP"/ 2>/dev/null || \
cp ~/Library/Group\ Containers/group.com.apple.usernoted/db2/db "$SNAP"/

# 2. Schema only. -readonly plus immutable=1 means SQLite will not create or
#    touch journal files, and .schema prints DDL, never row contents.
sqlite3 -readonly "file:$SNAP/db?immutable=1" ".schema"

# 3. Row *counts* are fine for debugging. Row contents are not.
sqlite3 -readonly "file:$SNAP/db?immutable=1" \
  "SELECT 'record', count(*) FROM record UNION ALL SELECT 'app', count(*) FROM app;"

# 4. Compute the fingerprint the same way StoreFingerprint does, to compare with a fixture manifest.
sqlite3 -readonly "file:$SNAP/db?immutable=1" \
  "SELECT group_concat(sql, char(10)) FROM sqlite_master WHERE sql IS NOT NULL ORDER BY name;" \
  | shasum -a 256

# 5. Delete the snapshot when done.
rm -rf "$SNAP"
```

If a schema change needs to go into an issue, paste the `.schema` output only, and check it for anything that is not DDL before posting. Table and column names are not private; the rows are.

> ⚠️ **Warning:** This is what we have observed, not an API. Column names may change in any macOS release; the fingerprint + adapter + fixture strategy exists for that reason. A schema diff from your own machine is the *input* to writing a new adapter and a new fixture — it is never itself checked in.

**Redaction of logs before sharing.** `BACKGLANCE_LOG_LEVEL=debug` output and `~/Library/Logs/Backglance/backglance.log` are designed to be content-free, but they do include your home directory in paths and the bundle IDs of apps that notified you. Before attaching a log to an issue:

```bash
sed -E "s#/Users/[^/ ]+#/Users/USER#g" ~/Library/Logs/Backglance/backglance.log > backglance-redacted.log
grep -nE 'titl|body|subt' backglance-redacted.log && echo "STOP: content-like keys found — do not share" || echo "ok"
```

If the second command prints anything, that is a bug in Backglance's logging; open an issue *about that* without attaching the log.

## Writing tests

Tests live in `Tests/<Package>Tests/` and are run by `Backglance.xctestplan` (all four bundles) or per package with `swift test --package-path Packages/<Package>`.

### Unit vs integration

| Kind | Where | Characteristics |
|---|---|---|
| Unit | `Tests/<Package>Tests/Unit/` | One type, no I/O, in-memory archive if a database is needed, sub-second |
| Integration | `Tests/<Package>Tests/Integration/` | Several types together: parser + adapter + archive, watcher + engine, hybrid search over a populated archive; may write to a temp directory |
| Fixture | `Tests/BackglanceCaptureTests/Fixtures/` | One per OS fixture; opens `store.db` read-only, runs the full pipeline, diffs against `expected.json` |
| UI | `Tests/BackglanceUITests/` | XCUITest for onboarding and the popover; launched with `--uitest-reset` and a temp `BACKGLANCE_ARCHIVE_PATH` |

Unit and integration tests are both XCTest; the split is a directory convention plus the `-only-testing` filter in `ci.yml`'s fast job. Anything that needs FDA is not a test — it is a manual step in [SETUP_GUIDE.md](./SETUP_GUIDE.md#verifying-capture-works).

### In-memory archive

`Archive(inMemory: true)` runs the full migration chain against `:memory:` and is what most Core and Search tests use.

```swift
import XCTest
@testable import BackglanceCore

final class RetentionJobTests: XCTestCase {
    private var archive: Archive!

    override func setUpWithError() throws {
        archive = try Archive(inMemory: true)
    }

    override func tearDown() {
        archive = nil
    }

    func test_whenNotificationOlderThanPolicy_thenSoftDeleted() throws {
        let now = Date(timeIntervalSince1970: 1_755_421_200)          // 2026-08-17 09:00 UTC
        let app = try archive.upsertApp(bundleID: "com.example.demo", now: now)
        let old = try archive.insert(
            ArchivedNotification.stub(appID: app.id, deliveredAt: now.addingTimeInterval(-40 * 86_400))
        )
        let fresh = try archive.insert(
            ArchivedNotification.stub(appID: app.id, deliveredAt: now.addingTimeInterval(-2 * 86_400))
        )

        let job = RetentionJob(archive: archive, defaultPolicy: .days30, clock: { now })
        let result = try job.run()

        XCTAssertEqual(result.softDeleted, 1)
        XCTAssertTrue(try archive.notification(id: old.id).isDeleted)
        XCTAssertFalse(try archive.notification(id: fresh.id).isDeleted)
    }

    func test_whenPolicyIsForever_thenNothingDeleted() throws {
        let now = Date(timeIntervalSince1970: 1_755_421_200)
        let app = try archive.upsertApp(bundleID: "com.example.demo", now: now, retention: .forever)
        _ = try archive.insert(
            ArchivedNotification.stub(appID: app.id, deliveredAt: now.addingTimeInterval(-400 * 86_400))
        )

        let job = RetentionJob(archive: archive, defaultPolicy: .days30, clock: { now })

        XCTAssertNoThrow(try job.run())
        XCTAssertEqual(try archive.countNotifications(includingDeleted: false), 1)
    }
}
```

`ArchivedNotification.stub(…)` and friends live in `Tests/BackglanceCoreTests/Support/Stubs.swift` and always use `example.com` bundle IDs and lorem text.

### Fixture tests

A fixture test opens a `store.db` from `Tests/Fixtures/SystemStore/` through the same `StoreSnapshot` path the app uses, resolves an adapter, parses every record, and compares with `expected.json`. Each OS has one such test class; adding a fixture means adding a class (three lines) — the shared harness does the work.

```swift
import XCTest
@testable import BackglanceCapture
@testable import BackglanceCore

/// Runs the full capture pipeline against a synthetic system store fixture.
/// Fixtures live in Tests/Fixtures/SystemStore/<os>/ and are generated by Scripts/make_fixture.sh.
class FixtureHarness: XCTestCase {
    /// Override in subclasses.
    class var fixtureDirectory: String { "" }

    private var fixtureURL: URL {
        Bundle.module.resourceURL!                                    // tests may force-unwrap
            .appendingPathComponent("Fixtures/SystemStore/\(Self.fixtureDirectory)")
    }

    func test_whenFixtureOpened_thenFingerprintMatchesManifest() throws {
        let manifest = try FixtureManifest.load(from: fixtureURL.appendingPathComponent("manifest.json"))
        let snapshot = try StoreSnapshot.open(readOnlyCopyOf: fixtureURL.appendingPathComponent("store.db"))
        let fingerprint = try snapshot.read { db in try StoreFingerprint.compute(db, osVersion: manifest.osVersion) }

        XCTAssertEqual(fingerprint.schemaHash, manifest.fingerprint.schemaHash)
        XCTAssertEqual(fingerprint.dbinfoVersion, manifest.fingerprint.dbinfoVersion)
    }

    func test_whenAdapterResolved_thenAllRecordsParseAsExpected() throws {
        let manifest = try FixtureManifest.load(from: fixtureURL.appendingPathComponent("manifest.json"))
        let expected = try FixtureExpectation.load(from: fixtureURL.appendingPathComponent("expected.json"))
        let snapshot = try StoreSnapshot.open(readOnlyCopyOf: fixtureURL.appendingPathComponent("store.db"))

        let fingerprint = try snapshot.read { db in try StoreFingerprint.compute(db, osVersion: manifest.osVersion) }
        let adapter = try XCTUnwrap(StoreAdapterRegistry.resolve(fingerprint: fingerprint))
        XCTAssertEqual(type(of: adapter).id, manifest.adapterID)

        let parsed: [ParsedNotification] = try snapshot.read { db in
            guard case .ok(let count) = try adapter.probe(db) else {
                return XCTFail("probe did not return .ok") as! [ParsedNotification]   // tests only
            }
            XCTAssertEqual(count, expected.notifications.count)
            let raws = try adapter.records(after: .start, in: db)
            return try raws.map { try RecordParser().parse($0) }
        }

        XCTAssertEqual(parsed.count, expected.notifications.count)
        for (got, want) in zip(parsed, expected.notifications) {
            XCTAssertEqual(got.bundleID, want.bundleID)
            XCTAssertEqual(got.uuid, want.uuid)
            XCTAssertEqual(got.title, want.title)
            XCTAssertEqual(got.body, want.body)
            XCTAssertEqual(got.presented, want.presented)
            XCTAssertEqual(got.deliveredAt.timeIntervalSince1970, want.deliveredAtUnix, accuracy: 0.001)
        }
    }

    func test_whenUnknownFingerprint_thenRegistryReturnsNilOrDegrades() {
        let bogus = StoreFingerprint(
            schemaHash: String(repeating: "0", count: 64),
            dbinfoVersion: nil,
            osVersion: OperatingSystemVersion(majorVersion: 99, minorVersion: 0, patchVersion: 0)
        )
        XCTAssertNil(StoreAdapterRegistry.resolve(fingerprint: bogus))
    }
}

final class FixtureMacOS14Tests: FixtureHarness { override class var fixtureDirectory: String { "macOS14" } }
final class FixtureMacOS15Tests: FixtureHarness { override class var fixtureDirectory: String { "macOS15" } }
final class FixtureMacOS26Tests: FixtureHarness { override class var fixtureDirectory: String { "macOS26" } }
```

Rules for fixture tests:

- Never construct a store path outside `Tests/Fixtures/`. A test that reads `~/Library/Group Containers/…` is rejected in review even if it is skipped in CI.
- If you change an adapter or the parser, regenerate the affected fixture's `expected.json` with `Scripts/make_fixture.sh` and explain the diff in the PR. A silently updated `expected.json` is a red flag.
- Fixture tests must pass on all three CI runners (`macos-14`, `macos-15`, `macos-26`), because the fixture pins the schema, not the host OS.

### Swift Testing

New pure-logic tests may use Swift Testing instead of XCTest. Keep to one framework per file.

```swift
import Testing
@testable import BackglanceCore

@Suite("OTPRedactor")
struct OTPRedactorTests {
    private let redactor = OTPRedactor.default

    @Test("redacts a code near an English keyword and records an event")
    func keywordEnglish() throws {
        var n = ParsedNotification.stub(bundleID: "com.apple.MobileSMS")
        n.body = "Your verification code is 000000"          // placeholder digits, not a real code

        let (out, event) = redactor.redact(n)

        #expect(out.body == "Your verification code is [code redacted]")
        #expect(event?.kind == .otp)
        #expect(event?.patternID == "otp.keyword.en")
    }

    @Test("leaves ordinary numbers alone")
    func ordinaryNumbers() {
        var n = ParsedNotification.stub(bundleID: "com.apple.mail")
        n.body = "Invoice 4821 is due on 2026-09-01"

        let (out, event) = redactor.redact(n)

        #expect(out.body == n.body)
        #expect(event == nil)
    }

    @Test("does not redact for apps outside the redaction list", arguments: ["com.example.demo", "com.tinyspeck.slackmacgap"])
    func otherApps(bundleID: String) {
        var n = ParsedNotification.stub(bundleID: bundleID)
        n.body = "code 000000"

        let (out, event) = redactor.redact(n)

        #expect(out.body == n.body)
        #expect(event == nil)
    }
}
```

## Code review checklist

Reviewers (and authors, before requesting review) go through this list. It is short on purpose.

**Correctness and safety**

- [ ] Adapter, parser, fingerprint, or `StoreSnapshot` changes come with fixture coverage: an updated or new fixture, `verify_fixture.sh` green, and the `expected.json` diff explained.
- [ ] No test, script, or code path reads a real store outside `StoreLocation` + `StoreSnapshot`; nothing opens the store writable.
- [ ] No notification content in logs (title, body, subtitle, sender, `userInfo`, `plistData`). `no_content_in_logs` passes; new log lines use `privacy: .public` only for identifiers and counts.
- [ ] Redaction still happens before insert; the `redactions` table never stores original text.
- [ ] No `!`, `try!`, `as!` outside `Tests/`; no `@unchecked Sendable` without a comment.
- [ ] Concurrency warnings introduced by the diff are fixed, not silenced.

**Data**

- [ ] Migrations are additive (`ALTER TABLE … ADD COLUMN`, new tables, new indexes). No column drops or type changes; no data rewrite outside a migration. New migration named `v<N>_<what>` and appended, never inserted.
- [ ] Timestamps use `UnixDate`; new columns follow the `snake_case` / `_at` / `is_` conventions in [DATABASE_SCHEMA.md](../architecture/DATABASE_SCHEMA.md).
- [ ] Anything that grows per-notification (new column, new index, embeddings) is measured against the ~1 KB/notification budget.

**UI**

- [ ] User-visible strings are in the String Catalog (`Localizable.xcstrings`); no inline literals in views. See [INTERNATIONALIZATION.md](../reference/INTERNATIONALIZATION.md).
- [ ] Every new interactive element has an accessibility label and, where relevant, a value and hint. VoiceOver order makes sense. See [ACCESSIBILITY.md](../reference/ACCESSIBILITY.md).
- [ ] New views have a `#Preview` using `PreviewData`; no real-looking sample content.
- [ ] Rules remain visual triage: nothing in the diff pretends to change system notification delivery.

**Performance**

- [ ] Budgets not regressed: idle CPU < 0.1 %, popover open-to-first-paint < 100 ms, FTS p95 < 50 ms, hybrid p95 < 250 ms, import of 10k store records < 10 s. If the change plausibly affects one, the PR says which and how it was checked. See [PERFORMANCE_GUIDE.md](../deployment/PERFORMANCE_GUIDE.md).
- [ ] No new work on the poll path that is not debounced or batched.

**Hygiene**

- [ ] `CHANGELOG.md` `[Unreleased]` updated when user-visible.
- [ ] Docs under `docs/` updated when behaviour, schema, env vars, or scripts changed.
- [ ] Commit/PR title is a conventional commit; branch is short-lived and rebased.
